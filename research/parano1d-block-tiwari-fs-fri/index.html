Parano1d under the Block–Tiwari FS-FRI metric

What security do the current Parano1d History parameters provide under Block and Tiwari's model for non-interactive FRI? This analysis develops their method step by step and derives the proved and conjectured estimates separately.

Abstract

Block and Tiwari define concrete security for a non-interactive FRI proof through the expected random-oracle query work Q/epsilon. This study maps the current Parano1d History parameters into that definition, derives the proved and conjectured RBR inputs and solves the integer optimization exactly.

The question behind a security-bit table

FRI is a proximity proof for Reed–Solomon codes and a core component of many transparent proof systems. Its original form is an interactive oracle proof (IOP): the verifier sends random challenges and inspects a small number of positions in large prover oracles. The Fiat–Shamir transformation removes that interaction by deriving the challenges from a random oracle. Once this transformation is applied, the relevant resource is no longer only the number of FRI queries inside one transcript. A cheating prover may query the random oracle many times, choose a favorable transcript and repeat the attack.

Block and Tiwari gave this attack an explicit work measure in On the Concrete Security of Non-interactive FRI. They start from a round-by-round (RBR) soundness error for the interactive protocol, apply the Fiat–Shamir compiler bound and minimize expected attack work over every random-oracle query budget.

This study asks one question: what security row do the current Parano1d History parameters obtain under the same definition, the same 256-bit oracle-output setting and the same whole-bit display convention? The proved RBR premise and the premise based on Block–Tiwari Conjecture 1 are derived and reported separately.

From interactive soundness to expected attack work

Let a malicious prover make at most QQQ classical queries to a random oracle

H:{0,1}∗⟶{0,1}κ.H:\{0,1\}^{*}\longrightarrow\{0,1\}^{\kappa}.H:{0,1}∗⟶{0,1}κ.

If the underlying interactive protocol has RBR soundness error εRBR\varepsilon_{\mathrm{RBR}}εRBR​, Lemma 1 of Block and Tiwari gives the following adaptive non-interactive random-oracle proof (NIROP) error:

εBT(Q,κ)=min⁡ ⁣{1,  QεRBR+3(Q2+1)2κ}.\varepsilon_{\mathrm{BT}}(Q,\kappa) =\min\!\left\{ 1,\; Q\varepsilon_{\mathrm{RBR}} +\frac{3(Q^2+1)}{2^\kappa} \right\}.εBT​(Q,κ)=min{1,QεRBR​+2κ3(Q2+1)​}.

The first term charges the interactive RBR error across QQQ oracle attempts. The quadratic term is the finite cost of compiling the public-coin interaction through Fiat–Shamir. The outer minimum keeps the success probability at most one.

Definition 2 measures work rather than the success probability of one selected budget. A QQQ-query attempt that succeeds with probability εBT(Q,κ)\varepsilon_{\mathrm{BT}}(Q,\kappa)εBT​(Q,κ) requires

W(Q)=QεBT(Q,κ)W(Q)=\frac{Q}{\varepsilon_{\mathrm{BT}}(Q,\kappa)}W(Q)=εBT​(Q,κ)Q​

expected random-oracle queries to obtain a forgery with probability close to one by repetition. The concrete security exponent is therefore

λBT=log⁡2 ⁣(min⁡Q∈Z≥1W(Q)).\lambda_{\mathrm{BT}} =\log_2\!\left( \min_{Q\in\mathbb Z_{\ge1}} W(Q) \right).λBT​=log2​(Q∈Z≥1​min​W(Q)).

A protocol has λ\lambdaλ bits under this definition exactly when W(Q)≥2λW(Q)\ge2^\lambdaW(Q)≥2λ for every positive integer QQQ. The minimization over QQQ is part of the metric; choosing a convenient adversarial budget is not.

The current History parameter set

The protocol inputs were checked against Parano1d revision 2cce53fc31a0bc173661bf5e07efaa56d8dc661b. HistoryStep is the recursive proof of a block's exact transition from its parent State to its child State. B64 and B255 enforce the same transition relation with capacities for at most 64 and 255 user-transaction pages. Their BaseFold codewords contain 2202^{20}220 and 2212^{21}221 positions respectively, but both classes use the same rate and query count.

Two RBR premises for one parameter set

The proved History RBR bound

The current History theorem analyzes the decommitted public-coin IOP over GF(2128). At relative distance 2/52/52/5, every candidate retained for the final query move agrees with the initial 32-column oracle on at most a 3/53/53/5 fraction unless an earlier verifier challenge falls into a counted exceptional set.

The 32 columns are packed into one Reed–Solomon word over a fixed degree-32 extension. Multiplicity-five list decoding leaves at most eleven initial candidates. List-correlated agreement carries any later fold candidate back to that fixed list; switching among candidates at an algebraic challenge is then paid by a union of their root sets rather than assumed away. The largest per-candidate algebraic degree is 127.

Why the global optimization reduces to two integers

Write a=εRBRa=\varepsilon_{\mathrm{RBR}}a=εRBR​ and b=3/2256b=3/2^{256}b=3/2256. Before the probability cap is reached,

W(Q)=QaQ+b(Q2+1)=1a+b(Q+1/Q).W(Q) =\frac{Q}{aQ+b(Q^2+1)} =\frac1{a+b(Q+1/Q)}.W(Q)=aQ+b(Q2+1)Q​=a+b(Q+1/Q)1​.

For positive integer QQQ, the quantity Q+1/QQ+1/QQ+1/Q is nondecreasing. Thus W(Q)W(Q)W(Q) is nonincreasing throughout the uncapped region. After the error reaches one, W(Q)=QW(Q)=QW(Q)=Q and is strictly increasing. The global minimum is therefore one of two adjacent integers: the largest Q0Q_0Q0​ whose uncapped error is below one, or Q1=Q0+1Q_1=Q_0+1Q1​=Q0​+1, the first capped point.

This argument covers every positive integer query budget. Exact integer binary search locates the boundary, and one rational comparison selects between the two candidates.

What the two columns show

The provable Parano1d value is higher than every non-lambdaworks value in the 2024 snapshot, including 67 for the Miden 128-bit configuration. Among the three lambdaworks rows, it is above the 80-bit configuration and below the 100- and 128-bit configurations. Block and Tiwari singled out lambdaworks as the only family in their snapshot whose proved values stayed close to all of its targets.

Reproducing the integer certificates

The public workbench contains the exact optimizer in crates/block-tiwari-rom and pins both results with regression tests:

git clone https://github.com/ignotusnemo/parano1d-qrom.git
cd parano1d-qrom

cargo test --release --locked --workspace
cargo run --release --locked -p scenarios -- block-tiwari-rom

No floating-point value is used to decide either reported bit. A reproduction needs arbitrary-precision integers and performs four steps:

  1. instantiate the uncapped numerator for the selected RBR premise;
  2. binary-search the largest positive integer Q0Q_0Q0​ for which that numerator is smaller than its denominator;
  3. compare W(Q0)W(Q_0)W(Q0​) and Q0+1Q_0+1Q0​+1 as exact rationals;
  4. compare the winning rational against consecutive powers of two.

For the proved premise, the two power-of-two tests can be written without division as
