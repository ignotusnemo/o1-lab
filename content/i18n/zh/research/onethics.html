我目睹许多区块链逐渐变成它们原本要摧毁的东西。历史无限增长，验证越来越沉重，人们不再自己判断真相，而是从 API、浏览器、交易所、基金会和数据中心租用别人眼中的现实。

这不是去中心化。这是租来的验证。

Parano1d 改变了区块链架构，但架构本身无法保证网络一直去中心化。它能让独立参与切实可行，却不能强迫任何人这样做。用户仍然必须把自己当作参与者，而不是顾客。

ONETHICS 不是道德权威，也不是由基金会强制执行的行为规范。它是一套运行纪律，服务于一张本来就不应存在可信运营者的网络。

1. 亲自验证

不要把区块浏览器、交易所或 API 当成事实来源。它们是方便的界面，不是共识。

打开 Parano1d GUI，使用其中的 Search 页面。它不是连接到别人服务器的轻钱包，而是在你的电脑上运行一个完整节点：本地验证工作量证明、区块头、HistoryStep 与 Live State，转发网络数据，并参与 P2P 网络。

只要它在运行，你就不是借用某家公司的网络视图。你在亲自确定规范 State，同时帮助其他节点交换数据。

当服务之间给出不同答案、突然消失，或认为回答你的查询已无利可图时，这一区别最为重要。便利很有用，但便利不是验证。

2. 保持共享 State 紧凑

每个仍然有效的 UTXO 都占用一个 State 槽位，而每个完整节点都必须承载这些槽位。历史交易体可以在重组窗口结束后被删除；尚未结束的义务则不能消失，因为网络仍要防止它们被重复花费。

当 18 个具有硬最终性的区块头中至少有 10 个记录到不低于 75% 的占用率时，State 域会扩容。每次扩容还会让区块补贴进入下一个减半档位，直到永久的 1 NOID 下限。

因此，合并输出不只是钱包维护。如果钱包积累了许多小额 UTXO，应当定期合并。GUI 一次最多可把 64 个 UTXO 合成一个输出，释放其余槽位。合并仍支付普通交易费，但由于它缩小 Live State，不收取 State-growth burn。

矿池应设置合理的付款阈值，用户也应合并积累的小额输出。这些做法都不是中央命令，却能减轻每个节点承受的负担，并让当前补贴档位维持更久。

扩容被有意设计为不可逆。一旦网络已经承诺更大的 State 域，此后占用率下降不会重写历史，也不会恢复先前补贴。应在不必要的压力永久化之前保持 State 紧凑。

3. 保存自己的证明

完整区块体离开 18 区块重组窗口后，Parano1d 会将其删除。永久保留的紧凑区块头仍承诺交易根，但网络不是你的私人交易档案馆。

付款 receipt 保存交易摘要，以及从该交易通往永久区块头的 Merkle 路径。原始区块体被删除后，它仍然可以独立验证。网络保存锚点；你保存对自己真正重要的那份证据。

请导出重要 receipts，或保留 wallet.receipts。Receipt 无法从钱包密钥重新派生。主密钥证明你控制资产，却不能重建一笔旧付款曾经发生的证据。

不要期待浏览器、交易所、基金会或最初的开发者替你保存证据。某个事实对你重要，就应当由你携带它的证明。

4. 保护控制资产的密钥

钱包密钥是控制 NOID 的唯一凭据。这里没有密码重置，也没有恢复客服。在接收资产或开始挖矿之前，先制作一份私密的离线备份。

在 GUI 中：

Settings → EXPORT KEY → COPY KEY

在命令行中：

parano1d --export-wallet-secret

使用自定义数据目录时：

parano1d --data-dir /path/to/data --export-wallet-secret

也可以直接保存 wallet.key：

Linux/macOS: ~/.parano1d/data/wallet.key
Windows:     %USERPROFILE%\.parano1d\data\wallet.key
Custom node: DATA_DIR/wallet.key

导出的秘密是一串 64 位十六进制字符。必须离线、私密保存，绝不要粘贴到网站、issue、聊天或客服消息中。

如果钱包由照片生成，该照片只是派生同一个普通 256 位钱包密钥的输入。你可以保存完全相同的原始文件、导出十六进制秘密，或复制 wallet.key；最好在彼此分离的私密位置保存多种备份。解码后的像素必须完全相同。缩略图、截图、编辑过的图片、云端预览或聊天软件中的副本，都可能派生出另一个密钥。

不要把唯一的备份留在同一台电脑上。

不要成为下一个 James Howells。

5. 验证主张，而不是营销

向后量子安全迁移，并不只是替换某一种签名算法。采用后量子原语，也不会自动让整个协议具备后量子安全性。

钱包授权、State 转换、承诺、递归验证、Fiat–Shamir 编译、随机预言机模型，以及从创世区块开始的完整有效性路径，都必须放在一起分析。每项主张都有适用范围，每份证明都有前提。

安全目标和猜想不是证明。从另一套参数的论文中复制一个巨大数字也不是证明。营销不是可靠性。

不要因为本文要求你信任 Parano1d 就选择信任。阅读前提，检查源码，复现可执行证书，挑战其中的假设。如果发现成本更低的攻击，就把它公开。

Parano1d 从架构中移除了历史债务，却没有移除用户自己的责任。

亲自验证事实。保持共享 State 紧凑。保存自己的证明。
