This is not a PCS ranking

The repository does not contain one linear contest where a succession of polynomial commitments were benchmarked under identical conditions and the fastest won. It contains a sequence of implementation boundaries. Early work needed a practical batched opening for AIR traces. Interleaved binary-field work needed to bind many columns efficiently. Recursive HistoryStep later needed to replay the verifier inside a fixed field relation.

Each construction solved a different problem. This retrospective records the implemented trail without pretending that measurements from one stage are a fair benchmark of another.

Ladder-batched FRI and VSHIFT

The May 2 implementation added a ladder-batched FRI opening and a VSHIFT gadget. A CarryRippleAir benchmark exercised a 64-bit ripple-carry adder with one shifted column. Per-slot ladder reductions were followed by one multipoint FRI opening rather than one FRI proof per slot.

Interleaved FRI-Binius

On May 16 the codebase gained an interleaved polynomial commitment over the binary tower field. Columns were encoded and committed together, compact FRI supplied low-degree testing, and mixed openings batched values across columns and points. The design matched the rest of the binary-field stack better than treating each column as an unrelated scalar polynomial.

The first implementation was not the end of the security work. It later exposed the commit-to-A, open-from-A′ gap described in Binding a compact FRI opening back to its committed source. The June 21 repair added query-level authentication from compact FRI to the encoded source commitment.

The verifier became the workload

For recursion, native verification speed is not the only metric. Every hash, fold, challenge and query authentication must be represented inside the outer relation. A commitment verifier with an awkward trace can be cheap natively and expensive recursively.

The BaseFold work implemented the verifier replay in FieldR1cs: transcript absorption, sumcheck checks, fold layers, query authentication and terminal consistency. That enabled the same-class recursive fixed point described in Closing the recursive verifier at a real fixed point.

What the trail changed

Four conclusions survived the implementation changes:

  1. opening bytes have to be measured separately from the elegant algebra that produces the claims;
  2. a mixed opening needs a visible source-binding path, not only a canonical transcript;
  3. recursive cost is a property of the verifier trace, not a scalar native benchmark;
  4. proof geometry has to be fixed early enough that matrices and release artifacts can be authenticated reproducibly.

Why preserve superseded implementations

The CarryRipple report and early FRI-Binius commits are not production recommendations. They are evidence. They show which cost dominated, which theorem was missing and which interface forced the next construction. A final architecture without that record makes the research look inevitable; it was not.
