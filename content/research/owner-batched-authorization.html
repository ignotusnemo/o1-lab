The duplicated wallet proof

The early wallet wire format carried two proof objects. A public-logic STARK proved balances, counts and output arithmetic. An AuthGKR proof established knowledge of the spending secret. When the transaction entered a block, the miner rebuilt the public transaction relation from the transaction body and proved it again inside the canonical block relation.

The wallet STARK was therefore not the authority for the accepted transition. It duplicated public work that every mempool and block already had enough data to check.

BeforeTx body + logic STARK + AuthGKRPublic arithmetic proved twice
→
AfterTx body + authorization capsulePublic logic checked natively, then proved canonically in the block

Separate public validity from ownership

The auth-only transition made the boundaries explicit:

  • the mempool derives and checks the exact public predicate from the transaction body;
  • the wallet proves only the private fact—knowledge of the secret controlling the selected inputs;
  • the block witness rebuilds public transaction logic from canonical transaction order;
  • the accepted-block proof establishes the final state transition.

The authorization statement is verifier-derived. The wallet cannot choose a more convenient statement and attach it to the same body. Strict decoding rejects trailing bytes, unknown variants and a proof built for the wrong transaction shape. Mutation tests changed owners, bodies, proof fields and secret sets and required rejection.

The first auth-only result

The June 23 benchmark measured the transition before later PagedSpend work. Standard one-to-eight-input transactions produced authorization proofs in roughly 76–79 ms, while the twenty-five-input sweep shape took roughly 250–270 ms. The old wallet STARK contribution was zero bytes after the change.

One owner, one statement

The next step replaced shape-specific per-transaction authorization with a canonical owner-batched statement. Inputs controlled by the same master secret are grouped under one logical authorization claim. The verifier derives the owner and selected input set from the transaction body and authenticated parent state.

This is particularly important in a bounded-slot UTXO system. A wallet may hold many small outputs. Consolidating or spending them should increase public hashing and intent size, not multiply zero-knowledge proofs by the number of pages.

PagedSpend at maximum fan-in

PagedSpend represents one atomic intent across physical pages. The production boundary allows up to 128 logical pages and 1,020 inputs in one group. The wallet builds exactly one witness-hiding capsule for that group.

What zero knowledge hides

The capsule hides the spending secret and freshly randomizes the proof. It does not turn ParanO(1)d into a confidential-transaction system. Owners, values, slots and transaction structure remain public while the transaction body is available. The private witness answers a narrow question: did the sender know the secret that derives the authenticated owner?

That narrow boundary is a strength. Public arithmetic does not need zero knowledge, and hiding it would make validation more expensive without changing ownership security.

The design consequence

Removing a proof can improve a proof-native system when the removed proof duplicated a relation that is authoritatively established elsewhere. The decisive step was not an optimization trick; it was identifying which proof speaks for which boundary. Once public validity, private authorization and canonical state transition were separated, owner batching followed naturally.
