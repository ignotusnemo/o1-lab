Аннотация

Block и Tiwari определяют конкретную безопасность неинтерактивного FRI через ожидаемое число запросов Q/epsilon к случайному оракулу. В этом исследовании текущие параметры Parano1d History переводятся в их определение, отдельно выводятся доказанная RBR-предпосылка и предпосылка на основе гипотезы, а целочисленная оптимизация решается точно.

Block и Tiwari приводят для каждой конфигурации FRI три числа: заявленный целевой уровень, доказуемую оценку после Fiat–Shamir и оценку на основе гипотезы. Два расчётных столбца измеряют ожидаемое число запросов к случайному оракулу, необходимое для успешной подделки. Первые восемь строк ниже воспроизводят их опубликованное сравнение; последняя добавляет текущие параметры Parano1d History по тому же определению и с тем же представлением в целых битах.

128 бит — заявленный целевой уровень, а не вычисленная граница. Значение 92 бита использует доказанную RBR-предпосылку History. Значение 126 бит получается после замены этой предпосылки Гипотезой 1 Block–Tiwari. Что стоит за таблицей битов безопасности

FRI — это доказательство близости для кодов Рида—Соломона и один из основных компонентов многих прозрачных систем доказательств. Изначально FRI является интерактивным доказательством с оракулом (IOP): проверяющая сторона посылает случайные вызовы и читает небольшое число позиций в больших оракулах доказывающей стороны. Преобразование Fiat–Shamir устраняет интерактивность, получая вызовы из случайного оракула. После такого преобразования важным ресурсом становится не только число FRI-запросов внутри одной транскрипции. Недобросовестная доказывающая сторона может многократно обращаться к случайному оракулу, выбирать выгодную транскрипцию и повторять атаку.

Block и Tiwari задали явную меру этой работы в статье On the Concrete Security of Non-interactive FRI. Они начинают с пораундовой (round-by-round, RBR) ошибки корректности интерактивного протокола, применяют границу компилятора Fiat–Shamir и минимизируют ожидаемую трудоёмкость атаки по всем бюджетам запросов к случайному оракулу.

В этом исследовании поставлен один вопрос: какую строку безопасности дают текущие параметры Parano1d History по тому же определению, при той же 256-битной длине выхода оракула и с тем же представлением результатов в целых битах? Доказанная RBR-предпосылка и предпосылка на основе Гипотезы 1 Block–Tiwari выводятся и публикуются отдельно.

От интерактивной корректности к ожидаемой трудоёмкости атаки

Пусть злоумышленник делает не более QQQ классических запросов к случайному оракулу

H:{0,1}∗⟶{0,1}κ.H:\{0,1\}^{*}\longrightarrow\{0,1\}^{\kappa}.H:{0,1}∗⟶{0,1}κ.

Если RBR-ошибка корректности исходного интерактивного протокола равна εRBR\varepsilon_{\mathrm{RBR}}εRBR​, то Лемма 1 Block и Tiwari даёт следующую ошибку адаптивного неинтерактивного доказательства в модели случайного оракула (NIROP):

εBT(Q,κ)=min⁡ ⁣{1,  QεRBR+3(Q2+1)2κ}.\varepsilon_{\mathrm{BT}}(Q,\kappa) =\min\!\left\{ 1,\; Q\varepsilon_{\mathrm{RBR}} +\frac{3(Q^2+1)}{2^\kappa} \right\}.εBT​(Q,κ)=min{1,QεRBR​+2κ3(Q2+1)​}.

Первое слагаемое учитывает интерактивную RBR-ошибку на протяжении QQQ попыток обращения к оракулу. Квадратичное слагаемое — конечная цена компиляции протокола с публичными случайными монетами посредством Fiat–Shamir. Внешний минимум ограничивает вероятность успеха единицей.

Определение 2 измеряет работу, а не вероятность успеха при одном выбранном бюджете. Попытка с QQQ запросами и вероятностью успеха εBT(Q,κ)\varepsilon_{\mathrm{BT}}(Q,\kappa)εBT​(Q,κ) при повторении требует в среднем

W(Q)=QεBT(Q,κ)W(Q)=\frac{Q}{\varepsilon_{\mathrm{BT}}(Q,\kappa)}W(Q)=εBT​(Q,κ)Q​

запросов к случайному оракулу, чтобы получить подделку с вероятностью, близкой к единице. Поэтому показатель конкретной безопасности равен

λBT=log⁡2 ⁣(min⁡Q∈Z≥1W(Q)).\lambda_{\mathrm{BT}} =\log_2\!\left( \min_{Q\in\mathbb Z_{\ge1}} W(Q) \right).λBT​=log2​(Q∈Z≥1​min​W(Q)).

Протокол имеет λ\lambdaλ бит безопасности по этому определению тогда и только тогда, когда W(Q)≥2λW(Q)\ge2^\lambdaW(Q)≥2λ для каждого положительного целого QQQ. Минимизация по QQQ является частью метрики: произвольно выбрать удобный бюджет злоумышленника нельзя.

Две RBR-предпосылки для одного набора параметров

Доказанная RBR-граница History

Теорема для текущего History рассматривает IOP над GF(2128) с публичными случайными монетами, где обязательства заменены прямым доступом к оракулам. При относительном расстоянии 2/52/52/5 каждый кандидат, сохранившийся до финального шага запросов, совпадает с исходным 32-столбцовым оракулом не более чем в доле 3/53/53/5 позиций, если только один из более ранних вызовов проверяющей стороны не попал в явно учтённое исключительное множество.

Тридцать два столбца упаковываются в одно слово Рида—Соломона над фиксированным расширением степени 32. Списочное декодирование кратности пять оставляет не более одиннадцати исходных кандидатов. Теорема list-correlated agreement — коррелированного согласия списков — связывает любой кандидат после свёрток с этим фиксированным списком. Переключение между кандидатами на алгебраическом вызове оплачивается объединением их множеств корней, а не отбрасывается предположением о фиксированном кандидате. Наибольшая алгебраическая степень для одного кандидата равна 127.

Почему глобальная оптимизация сводится к двум целым числам

Обозначим a=εRBRa=\varepsilon_{\mathrm{RBR}}a=εRBR​ и b=3/2256b=3/2^{256}b=3/2256. Пока вероятность не отсечена единицей,

W(Q)=QaQ+b(Q2+1)=1a+b(Q+1/Q).W(Q) =\frac{Q}{aQ+b(Q^2+1)} =\frac1{a+b(Q+1/Q)}.W(Q)=aQ+b(Q2+1)Q​=a+b(Q+1/Q)1​.

Воспроизведение целочисленных сертификатов

В публичном стенде точный оптимизатор находится в crates/block-tiwari-rom, а оба результата закреплены регрессионными тестами:

git clone https://github.com/ignotusnemo/parano1d-qrom.git
cd parano1d-qrom

cargo test --release --locked --workspace
cargo run --release --locked -p scenarios -- block-tiwari-rom

Ни одно значение с плавающей точкой не участвует в выборе публикуемого целого числа. Для воспроизведения достаточно целых чисел произвольной точности и четырёх шагов:

  1. задать числитель неотсечённой ошибки для выбранной RBR-предпосылки;
  2. двоичным поиском найти наибольшее положительное целое Q0Q_0Q0​, при котором числитель меньше знаменателя;
  3. точно как рациональные числа сравнить W(Q0)W(Q_0)W(Q0​) и Q0+1Q_0+1Q0​+1;
  4. сравнить выигравшее рациональное число с соседними степенями двойки.

Для доказанной предпосылки две проверки степеней двойки записываются без деления:

Для предпосылки при гипотезе нужно заменить DDD на 22562^{256}2256, а N(Q)N(Q)N(Q) — на Q2128+3(Q2+1)Q2^{128}+3(Q^2+1)Q2128+3(Q2+1). Напечатанных выше целых чисел на границе достаточно как регрессионных векторов для независимой реализации на SageMath, Rust, Python или в другой системе компьютерной алгебры.
