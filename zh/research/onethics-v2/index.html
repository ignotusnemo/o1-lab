协议实践去中心化2026年10月12日

ONETHICS ①

验证当下。了解自己的权利。保存证明。为后来者建设。

作者 Ignotus Nemo6 分钟阅读参与者准则
分享分享到 X
本文目录1. 亲自验证，不借用判断2. 权利，而非承诺3. 保存自己的证明4. 你的 State 是共同责任5. 独立建设，自主判断6. 挑战密码学7. 为后来者建设

Parano1d 让独立验证变得可行：验证当下，保存自己需要的证据，并为未来参与者留下一个仍然可以自主验证的网络。V2 将这种实践扩展到合约。我们现在可以检查谁拥有有效权利、哪些规则约束权利的使用，以及行使权利后还会留下什么证据。

网络用户和建设者的实践，让这种独立性持续下去。

ONETHICS 是参与者的实践准则。它的原则出于自愿，其权威来自每个人能够亲自验证的事实。

1. 亲自验证，不借用判断

每个钱包都应成为网络参与者，能够自主确认自己接受的内容。浏览器、API 或交易所可以提供有用的服务。共识事实来自对网络规则和证据的验证。

Parano1d GUI 在你的计算机上运行完整节点。它检查工作量证明、区块头、HistoryStep 和经过认证的当前 State，转发网络数据，并加入 P2P 网络。证明确立有效性，工作量证明确立规范顺序。

种子节点帮助你发现对等节点。它们负责引导你的节点进入网络；收到的数据仍须经过本地验证。独立的对等节点和入口，让参与能够在某个服务或种子节点消失后继续。

如果外部服务报告错误余额或显示不同历史，你自己的验证器能够提供检查其主张的依据。如果服务关闭，你仍然可以通过网络继续参与。钱包应清楚显示同步状态，让你区分最后一次验证的 State 和当前链状态。

2. 权利，而非承诺

承诺不是合约。合约不是收据。

有人可以承诺支付给你 100 NOID。这说明了他的意图。已经注资的合约提供了可以检查的内容：被承诺绑定的程序和策略、各方权限、金额，以及价值可以转移的条件。

验证公开条款是否与经过认证的当前 State 中的承诺一致，以及具体输出实例是否仍未花费。检查谁可以领取、收回或关闭合约，允许的高度和限额是什么。注资证明价值存在；条款决定你对这些价值实际拥有哪些权利。

一次成功调用证明了被授权的转换。它可以完成支付、更新剩余权利或结束义务。保存的合约收据能够在旧区块体被剪枝后，继续证明这次具体行动。

这样，协议的每个阶段都有自己的证据：承诺表达意图，已注资合约确立可执行的当前权利，收据记录已经完成的履行。ONETHICS 既涉及我们如何持有资金，也涉及我们如何彼此协作。

3. 保存自己的证明

网络保存有效性。你保存对自己重要的证据。

节点保留最近 42 个完整区块。更旧的区块体和交易会被剪枝；永久区块头保留交易根。保存的支付收据携带支付数据和 Merkle 包含证明。将其根与规范区块头核对，可以确定这笔支付属于哪条链。

合约收据还保存公开条款，以及已接受调用或关闭的证据。导出重要收据和合约文件，并保留自己掌控的副本。其他参与者可以据此检查事件，无须依赖原始应用或归档运营者。

当前 State 和历史收据回答不同的问题。State 认证已知权利现在仍然有效。收据证明过去发生的行动。在使用收据描述的后继状态前，应在当前 State 中检查准确的槽位和创建标识：该输出可能已经被花费。

将钱包秘密与公开合约条款和收据分别备份。秘密控制普通资金和你的合约权限。恢复秘密可以恢复这些权限；恢复合约程序、公开开封数据或过去的交互，则需要相应证据。秘密应保密并离线保存，另留一份副本在日常使用的设备之外。

4. 你的 State 是共同责任

共享 State 不会因为由别人存储就变得免费。

每个有效输出都占用完整节点需要维护的槽位。支付和合约使用同一项共享资源。花费会清空已占用槽位，新输出可以用新的创建标识复用它们。持续运行的合约能够更新权利，而无需将所有旧状态累积到当前活跃集合中。

净新增活跃槽位的费用随占用率上升，这部分增长费用会被销毁。将多个输入合并为更少输出的归集会释放槽位，无须支付 State 增长销毁费用；普通交易费用仍然适用。合约操作按同样规则为自己的实际活跃状态占用付费。

选择支付阈值、归集方式和应用结构时，应考虑这项共同成本。保留许多小额输出可能有用途。保留它们应当是经过考虑的选择。高效使用 State 能够减少其他参与者承担的存储负担。

V2 将存储定价与发行分开。区块补贴遵循高度计划；State 域扩展时，这项计划保持不变。负责任地使用 State，有助于网络持续适合独立运营者。

5. 独立建设，自主判断

开源意味着任何人都能建设。它不意味着所有人都必须信任建设出来的东西。

人们可以在 Parano1d 上开发钱包、矿池、浏览器和应用。每个建设者都应对自己的软件、基础设施和承诺负责。列入 community builds 表明一项生态贡献；官方身份或背书需要另外作出明确声明。

第三方钱包开发者代表自己的钱包，矿池运营者代表自己的矿池。用户应知道自己运行的是谁的软件、谁控制密钥、哪些内容在本地验证，以及应用依赖哪些服务。

核心开发优先关注协议正确性、独立验证和切实可行的节点运行。需要归档或完整历史统计的建设者，应自行组织数据收集和存储，并向用户明确展示缺失。

Ignotus Nemo 不应成为网络中每个应用的永久质量裁判。建设者需要自行决策的空间。参与者需要证据，以及自主判断的自由。

6. 挑战密码学

如果你能推翻一个假设，就公开证据。网络正是这样变得更强。

针对主张所描述的准确构造进行验证，也包括我们的主张。有效性路径涵盖授权、执行、承诺、递归验证和 Fiat–Shamir 编译。应将定理条件、安全证书、源代码版本和生产参数放在一起审查。

noid.network 发布研究任务、主张依赖关系和经过审阅的证据。复现一项计算，检查一条界限，寻找成本更低的攻击或响应电路。报告模型、参数、准确源代码提交、成本核算和复现程序，让其他人能够检查结果。只要清楚说明方法和局限，失败的攻击和未得出明确结论的实验也有记录价值。

当前 v2 评估保留了明确条件：全根组合与编译器提升、固定 Poseidon2b 相对理想模型的偏差、诚实的公开预处理，以及响应电路的资源成本。完整自适应编译器闭合、固定哈希条件和最低响应成本仍是研究义务。这些都是具体的研究对象。

复现计算确立的是实际检查过的结果。对完整密码学进行独立审计，范围更广，涵盖构造、假设、组合和实现。公布每项审查的范围，让未来读者能够判断哪些证据支持某项主张。

7. 为后来者建设

去中心化还有时间维度。想象一个五十年后加入的人。他应该能够认证当下，无须依赖浏览器、早已消失的开发者，或继承了对过去独占控制的机构。

做到这一点需要的不只是删除旧数据。未来参与者需要公开的协议规则、可复现的实现、保存下来的验证产物，以及被接受的转换确实承载其声称历史的证据。

V2 已经包含一个明确定义的转换，绑定旧链祖先关系，并允许旧证明矩阵退役。这是跨代延续的具体一步。更长期的目标，是在不同密码学代际之间进行经过认证的转换，定义准确的转换关系，并提供涵盖两个代际的安全分析。每次转换都必须在明确声明的条件下保留可独立验证的历史。

网络用户应当希望 Parano1d 逐渐独立于 Ignotus Nemo。公开足够的材料，让另一支团队能够实现规则、审查假设、复现产物并继续工作。我们的继任者应当继承这种能力。

当下证明过去。让下一位参与者仍然能够验证。
